# Assistant workflow and feature coverage

## End-to-end workflow

1. `make dev` starts the loopback Python API (8765), Node bridge (8787) and holographic React UI (5802). Credentials stay in the repository's ignored `.env`. Jarvis is the default screen; `?view=tasks` opens the existing Task Center.
2. Message accepts a typed request. INITIALISE enables the voice/boot flow after a user gesture and browser permissions. Local VAD detects segments; configured cloud STT transcribes them, or browser recognition supplies the fallback. Wake phrases activate conversation and follow-up listening.
3. The bridge creates a durable assistant cost session. Message offers Auto, Local text, and OpenAI tools. Availability and budget routing runs before inference. Local text uses Ollama without tool execution; OpenAI tools submits bounded context to Responses via Python. Switching to local preserves completed text answers, not camera images or tool outputs. Token counting precedes a spend reservation. Text deltas stream to captions and speech. Completion settles usage; unknown requests retain their reservation.
4. OpenAI function proposals select validated local UI/display/camera/SystemAI tools or explicitly allowlisted read-only MCP tools. Direct CDP is observation-only. Only completed turns enter retained context (last eight turns); each turn has at most twelve model/tool rounds. MCP discovery selects tools into the bounded schema list. No model gets a generic shell, approval, or resume capability. Turn/tool outcomes are audited without prompt or argument content.
5. UI tools alter colour, reactor, orbits, effects and display panels. Camera tools request explicit browser captures/watch frames. Search renders clickable source links in a blade. Image generation stores a PNG under the runtime artifact directory and shows it in a blade/orbit. Media access is bounded and proxied; HTML is sanitised.
6. Diagnosis, browser and desktop tools create scoped tasks linked to the conversation's budget. Manual tasks created in Task Center share that context too. Task Center retains the selected task across modal close/reopen and offers durable history. It exposes state, observations, canonical approvals, pause/stop/takeover, verification, audit and costs. Browser clicks require an explicit postcondition. The core chain remains goal -> DAG -> lease -> intent -> policy -> approval -> signed executor -> observation -> verification -> audit. Cancelled/completed/failed/taken-over tasks cannot be revived through pause/resume.
7. Speech uses a metered server provider, or browser/Kokoro fallback. Generated voices are identified in the voice label. Speaking during a response interrupts delivery; late frames cannot alter the new turn. Cancellation during startup, routing or audit preflight releases the next turn and prevents not-yet-started tools from dispatching. Already-started provider calls drain to settle usage. Already-started SystemAI tasks remain in History after interruption; late results cannot replace an explicitly selected task. Interruption never resets the shared budget and is not a rollback; use Stop/Take control for task control. Malformed bridge frames are ignored without breaking the UI.
8. Workspace tools exposes History, Memory, Alerts, Review, Routing and Audit. Notes are explicitly saved and local; exact-process alerts do not execute actions; reviews do not qualify/sign/replay skills. Child-task audit includes conversation turn/tool events, and costs cover linked tasks. Restart before dispatch requires fresh authorization; durably observed actions are verified without redispatch. Unknown commit status requires manual reconciliation. The events CLI is read-only and does not run recovery.

## API and provider coverage

- OpenAI Responses: text, images as input, streaming, function calls, encrypted reasoning context, token preflight and task usage.
- Speech: bounded audio upload -> transcriptions; bounded text -> MP3/WAV speech; shared spend/call/audio budgets and concurrent call accounting. Independent `SYSTEMAI_STT_PROVIDER` and `SYSTEMAI_TTS_PROVIDER` override the legacy shared provider. Deepgram Nova-3 supplies STT, Cartesia Sonic-3.6 supplies TTS, and Sarvam Saaras v4/Bulbul v4 Flash supports selectable Indian-language STT/TTS. Existing OpenAI/ElevenLabs paths remain supported.
- `DEEPGRAM_DIARIZE=true` enables the current diarization model; speaker/timestamp words are preserved in `/stt`, while voice commands consume only transcript text. Speaker IDs are segment-local, not persistent identities or authorization. Sarvam REST STT does not support diarization. Voice input uses local VAD segments (20 seconds maximum), not provider streaming WebSockets.
- Speech access requires a live bridge connection; closing during startup cannot register a late voice session. Already-started metered speech requests may still finish after interruption.
- Hosted tools: one web-search call per invocation with source links; single low-quality PNG generation with artifact persistence. User chooses compatible image model.
- Open models: installed Ollama text/vision/embedding models; optional browser Kokoro speech. This is adapter support, not installation of every open model.
- MCP: stdio, Streamable HTTP and explicitly configured legacy SSE. Examples are disabled, not verified account integrations. Each trusted server requires exact `allowedTools` names and a positive `usdPerCall` ceiling. Only read-named tools without mutation verbs are exposed. Names cannot prove remote semantics: review the connector before allowing it. Third-party generative/write workflows remain unavailable until they meet the signed action boundary; native OpenAI search/images remain available.

This release does not implement every OpenAI endpoint: native Realtime/WebRTC duplex speech, fine-tuning, batch jobs, vector stores/file search, video APIs and managed computer-use are not wired. The current audio workflow is turn-based STT -> Responses -> TTS. The supplied Jarvis features do not require those unrelated endpoints.

## Required private settings

Start from `.env.example`. Supply OPENAI_API_KEY, enable flag, compatible Responses model, verified token rates/date, task spend/call limits. For cloud speech supply enable flag, models, voice and positive estimates; for search/image supply estimates and image model. ElevenLabs requires positive `SYSTEMAI_ELEVENLABS_STT_MAX_CALL_COST_USD` and `SYSTEMAI_ELEVENLABS_TTS_MAX_CALL_COST_USD`. Zero/unverified rates fail closed. Speech/images/MCP use conservative configured estimates, not measured invoice charges; all share the Python ledger. Unknown connector completion leaves reservations held. Provider audio duration is estimated, not measured. Increase context/output limits deliberately for tool-rich requests.

Cloud content is sent to the configured provider. Responses requests use store=false; that is not a guarantee of zero provider retention. Camera frames leave the device only when sent through an explicitly requested model workflow. Generated files are local. The bridge checks loopback Host headers on HTTP and WebSocket requests, plus its configured browser Origin allowlist; these checks mitigate cross-site/rebinding access but are not authentication. Local HTTP interfaces are not production-authenticated IPC.

### Independent speech setup

Keys `DEEPGRAM_API_KEY`, `CARTESIA_API_KEY`, and `SARVAM_API_KEY` belong only in the ignored root `.env`, never frontend `VITE_*` variables. Select one provider per direction; Sarvam is an explicit alternative, not an automatic paid retry. Configure positive `SYSTEMAI_<PROVIDER>_<STT|TTS>_MAX_CALL_COST_USD` values and the shared `SYSTEMAI_OPENAI_MAX_TASK_SPEND_USD`, `SYSTEMAI_OPENAI_MAX_TASK_CALLS`, `SYSTEMAI_OPENAI_MAX_TASK_AUDIO_SECONDS` limits. These shared limits work even with OpenAI inference disabled. Changes require restarting the API/bridge and opening a new conversation; existing durable sessions retain their earlier limits.

STT reserves its configured per-call ceiling and 30 seconds of audio. Cartesia/Sarvam TTS reserve their configured full-input ceiling scaled by text length (4096/2500 characters respectively); this conservatively accounts for short streamed sentences without charging each as a full-length request. These are application reservations, not invoice measurements or account-wide/monthly caps. Provider subscription fees, tax, other clients and repeated new sessions are outside this ledger. Set provider-account spending controls too. Failed/unknown provider completion keeps the reservation; do not manually mark it settled without checking the provider.

The private development setup uses a $5 cap per new conversation, 100 external calls, 1800 estimated audio seconds, $0.01 per STT request, $0.30 per full Cartesia input and $0.15 per full Sarvam input. These deliberately padded estimates are not quoted provider prices. Review ceilings when changing models/plans. Cartesia defaults to the documented example voice UUID; select a different `CARTESIA_VOICE_ID` if desired. Sarvam supports `SARVAM_STT_LANGUAGE` (default auto-detect), `SARVAM_TTS_LANGUAGE` (default en-IN), and optional `SARVAM_SPEAKER` (must match Bulbul v4 personas).

Adapter contracts were checked against [Deepgram REST](https://developers.deepgram.com/reference/speech-to-text/listen-pre-recorded), [Cartesia bytes](https://docs.cartesia.ai/api-reference/tts/bytes), [Sarvam STT](https://docs.sarvam.ai/api-reference/speech-to-text/transcribe) and [Sarvam TTS](https://docs.sarvam.ai/api-reference/text-to-speech/convert). Cost ceilings were cross-checked with the official [Deepgram](https://deepgram.com/pricing), [Cartesia](https://www.cartesia.ai/pricing) and [Sarvam](https://www.sarvam.ai/api-pricing) pricing pages; live account rates may differ.

## Acceptance boundaries

Automated tests cover core authority/recovery/cost logic, mocked OpenAI audio/search/image/streaming, bridge function execution/session speech/origin rejection, Chrome CDP and UI build/modal smoke checks. Live OpenAI/ElevenLabs billing, microphone/speakers, camera/gesture calibration, third-party MCP accounts, native Cua permissions and signed desktop packaging need external credentials/hardware setup. Their absence is reported as unavailable, not fabricated success.
